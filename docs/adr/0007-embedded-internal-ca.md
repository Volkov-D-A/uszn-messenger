# ADR-0007: Встроенный публичный сертификат внутреннего CA

- Статус: Принято
- Дата: 2026-07-28

## Контекст

Сервер доступен только по HTTPS/WSS с сертификатом внутреннего CA. Установка корневого сертификата на каждую рабочую станцию вручную или через централизованные политики увеличивает стоимость развертывания клиента.

## Решение

Включать публичный сертификат внутреннего CA в комплект desktop-клиента. Go client core создает отдельный набор доверенных корней для соединений USZN Messenger и не зависит от системного хранилища сертификатов. React/WebView не соединяется с сервером напрямую.

При плановой ротации сначала распространяется клиент, доверяющий одновременно старому и новому CA. Сервер переключается на сертификат нового CA только после распространения переходной версии клиента. Закрытый ключ CA никогда не входит в клиентский комплект.

## Последствия

- Не требуется изменять системное хранилище Windows и Ubuntu или разворачивать отдельную клиентскую политику.
- Доверие ограничено соединениями приложения и не влияет на другие программы рабочей станции.
- Плановая ротация CA требует последовательного обновления клиента и сервера.
- Аварийная компрометация CA может потребовать ручной доставки обновленного клиента.
- Из-за отсутствия подписи релизов атакующий с доступом на запись к SMB может заменить клиент вместе со встроенным CA; этот риск уже принят в ADR-0006.
