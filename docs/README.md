# Документация USZN Messenger

USZN Messenger — автономный корпоративный desktop-мессенджер для одной организации. Целевые клиенты: Windows 10/11 x64 и Ubuntu 22.04 x64. Ближайшая программная веха — интерактивный Wails-прототип с мок-данными; сервер на этой вехе не реализуется.

## Основные решения

- Приложение поставляется только для desktop; web, mobile и macOS исключены из текущего объема.
- Развертывание on-premise в полностью изолированном контуре, одна организация на одну инсталляцию.
- Клиент: Wails v2, React и TypeScript. Сервер: модульный монолит на Go.
- Источник истины — PostgreSQL; вложения хранятся в серверной файловой системе.
- Реальное время — WebSocket, запросы и команды — REST/JSON.
- Сквозного шифрования нет; применяются TLS/WSS и инфраструктурное шифрование дисков.
- Клиент запускается общим launcher с SMB-ресурса, но рабочая версия исполняется из локального кеша.
- Первая программная веха — UX-прототип с детерминированными моками, без сетевого сервера.

Подробное обоснование решений находится в [ADR](adr/README.md).

## Глоссарий

| Термин | Значение |
| --- | --- |
| Организация | Единственный административный контур текущей инсталляции |
| Подразделение | Управляемая администратором часть оргструктуры; определяет область ролей и служебный чат |
| Тематический канал | Публичный или приватный групповой чат, не привязанный напрямую к подразделению |
| Чат подразделения | Групповой чат с централизованным членством по оргструктуре |
| Личный чат | Диалог двух сотрудников |
| Тег | Управляемая администратором метка пользователей для упоминаний, фильтрации и выбора аудитории |
| Объявление | Массовая рассылка, отображаемая в системном разделе «Объявления» |
| Критичное сообщение | Неизменяемое сообщение с доставкой, просмотром, явным подтверждением и сроком ознакомления |
| Подтверждение | Осознанное действие адресата «Ознакомлен», отличное от автоматического просмотра |
| DND | Режим «Не беспокоить», подавляющий все уведомления и включающий автоответ |
| Область действия (scope) | Набор подразделений или групп, внутри которого действует разрешение роли |
| Мягкое удаление | Скрытие содержимого с сохранением системной отметки и аудируемых метаданных |
| Курсор синхронизации | Последняя обработанная клиентом последовательность серверных событий |

## Правила ведения документации

- Язык документации — русский, формат — Markdown, схемы — Mermaid.
- Новое существенное архитектурное решение оформляется ADR; принятый ADR не переписывается, а заменяется новым.
- Изменения терминов сначала вносятся в этот глоссарий, затем во все зависимые документы.
- Открытые продуктовые и эксплуатационные решения заносятся в `open-questions.md` с ответственным этапом и рекомендуемым вариантом.
- Требования обозначаются стабильными идентификаторами `FR-*` и `NFR-*`; приемочные сценарии ссылаются на них.
