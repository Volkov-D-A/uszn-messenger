# ADR-0003: REST, WebSocket и восстановимая синхронизация

- Статус: Принято
- Дата: 2026-07-24

## Контекст

Клиент должен получать события в реальном времени, читать кеш без сети и без дубликатов догонять изменения после разрыва.

## Решение

Использовать REST/JSON для команд, истории, файлов и администрирования; WebSocket — для живых событий. Долговечные события получают монотонный sequence и доступны через `/sync`. Создающие команды требуют idempotency key.

## Последствия

- Повтор после потерянного ответа безопасен.
- Клиент хранит курсор и исходящую очередь в SQLite.
- Сервер хранит журнал событий достаточно долго для согласованного офлайн-окна.
- Эфемерные presence/typing-события могут теряться и не восстанавливаются.
